# T-11d — Themes: dreizehn Paletten, Leisten-Token, feste Marke — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die acht gewachsenen Paletten durch die **dreizehn** aus `ux-standards/references/themes.md` ersetzen, die fehlenden Token nachziehen, Status-Farben in heller/dunkler Stufe führen, den Marken-Verlauf vom Theme lösen — und das Ergebnis mit dem Prüfwerkzeug des Skills belegen statt zu schätzen.

**Architecture:** `base.scss` bleibt der einzige Ort der Paletten; jedes Theme trägt seinen Token-Satz im eigenen `[data-theme]`-Block. Die `--c-*`-Rückwärts-Aliase aus T-11b laufen hier aus. `useTheme` bekommt die neue Liste und folgt ohne gespeicherte Wahl der Systemeinstellung.

**Tech Stack:** SCSS (`base.scss`, `_variables.scss`), Vue 3 SFC, Vitest, `theme-tokens.py` (Prüfwerkzeug des Skills).

## Global Constraints

- **Werte werden KOPIERT, nicht abgetippt und nicht nachgerechnet.** Quelle ist einzig
  `~/.claude/skills/ux-standards/references/themes.md`. Der Skill sagt es wörtlich:
  > Hier wird nicht nachgerechnet. Die Werte sind einmal gelöst und geprüft worden; sie in einer zweiten App erneut zu berechnen liefert bestenfalls dasselbe Ergebnis und schlimmstenfalls ein leicht anderes — und dann heißen zwei Paletten gleich und sehen verschieden aus.

  Deshalb stehen in **diesem Plan bewusst keine Farbwerte**: Ein zweites Abtippen wäre eine zweite Fehlerquelle. Lies die Blöcke aus der Datei und übernimm sie.
- **Alles Theme-Abhängige gehört in den `[data-theme]`-Block**, nie auf `:root` mit `var()`-Verweis: Ein Custom Property mit `var()` wird dort ersetzt, wo es deklariert ist, und vererbt sich fertig aufgelöst. Die Theme-Vorschau (je Kachel ein eigenes `data-theme`) zeigte sonst 13× dasselbe Theme. In T-11b bereits beinahe passiert.
- **Vom Auftraggeber entschieden:** nur die Skill-Themes — StockInfos `earth`, `night`, `sunset`, `neon` entfallen ersatzlos; **keine** Umschreibung gespeicherter Wahl.
- **Wichtig zur Einordnung:** StockInfos altes `classic` (pflaume/korall) entspricht **keinem** Skill-Theme mehr. Der frühere Plan, es in `mangolila` umzubenennen, ist hinfällig — `mangolila` ist inzwischen *warmes Anthrazit*; der Pflaumen-Entwurf wurde im Skill ausdrücklich verworfen (Farbton 264° statt 304° der Marke, nur 19° von `aurora`). Die alten Paletten werden also schlicht ersetzt, nicht zugeordnet.
- **Marke ist themeunabhängig:** `--brand-from: 223 84 48`, `--brand-to: 129 44 124`, `--brand-contrast: 255 255 255`, Verlauf **135°**. `--brand-contrast` ≠ `--accent-contrast` — Letzteres wechselt mit dem Theme und ist in acht der dreizehn Paletten nahezu schwarz.
- Gate je Task: `npm run build` sauber **und** `npm test` grün.
- Arbeitsverzeichnis: `dashboard/`.

## Zwei Unstimmigkeiten in der Quelle — so wird damit umgegangen

Die Wertblöcke in `themes.md` sind **erzeugt** (`theme-tokens.py export`), der Fließtext ist von Hand. Wo beides auseinandergeht, **gilt der erzeugte Block**. Zwei Stellen sind betroffen:

1. **`carbon` und die Status-Farben.** Der Fließtext sagt zweimal, `carbon` bringe eigene, kräftigere Stufen mit. Im erzeugten `carbon`-Block stehen **keine** `--status-*`-Zeilen mehr. → `carbon` bekommt **keine** eigenen Status-Werte. Im Report vermerken.
2. **Die Aufzählung der dunklen Themes.** Der Fließtext nennt für die dunkle Status-Stufe „mangolila, classic, slate, ocean, forest, aurora" — das ist die alte Elfer-Liste. Tatsächlich sind **neun** Themes dunkel: die sechs genannten plus **`amber`**, **`petrol`** und **`carbon`**. → Regel anwenden („dunkle Themes bekommen die dunkle Stufe"), nicht die veraltete Aufzählung.

Beides **nicht selbst im Skill korrigieren** — melden, der Auftraggeber pflegt die Quelle.

```ts
/** Ohne eigene Wahl entscheidet die Systemeinstellung: dunkel → mangolila, hell → paper. */
function systemTheme(): ThemeKey {
  try {
    return window.matchMedia('(prefers-color-scheme: dark)').matches ? 'mangolila' : 'paper'
  } catch {
    return 'mangolila'
  }
}
```
